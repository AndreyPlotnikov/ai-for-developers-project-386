# Выбор тестов

Начните с критериев приёмки задачи. Для каждого сценария выберите уровень, на котором наблюдается проверяемый результат.

- **HTTP / Vitest.** Проверяйте правила домена, границы валидации, статусы и тела ответов, а также сохранение данных через `app.request()`. Размещайте тесты в `backend/tests/`.
- **E2E / Playwright.** Проверяйте критичные пользовательские сценарии, когда результат зависит от браузера. Это включает навигацию, работу с клавиатурой, переход фокуса, повтор после ошибки и восстановление после перезагрузки. Размещайте тесты в `frontend/e2e/`. [Инструкция по запуску](../../frontend/README.md#e2e-тесты)
- **Unit.** Добавляйте прямые тесты для отдельных алгоритмов со сложными пограничными случаями, когда так проще проверить варианты входа и результата.

Если сценарий затрагивает API и интерфейс, проверяйте на каждом уровне свой наблюдаемый результат. Например, при повторе создания типа встречи HTTP-тест проверяет, что сервер возвращает тот же тип без дубликата, а Playwright проверяет, что после перезагрузки страницы пользователь может продолжить ту же попытку.

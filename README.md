## Сценарий

Сценарий записан по референсу [Cal.com](https://cal.com): путь от создания типа встречи до появления записи у владельца.

Владелец:

1. Открывает список типов встреч и создаёт новый: название, описание, длительность (например, «Консультация», 30 минут).
2. Новый тип сразу доступен гостям по своей ссылке. Свободное время считается по рабочим часам владельца (в Cal.com по умолчанию пн–пт 9:00–17:00 в его часовом поясе).

Гость:

3. Без регистрации открывает страницу владельца и выбирает тип встречи.
4. Видит календарь с ближайшими днями и выбирает дату. Справа появляются свободные слоты, длина слота равна длительности типа встречи.
5. Выбирает слот. Время, уже занятое любой встречей, в списке не показывается.
6. Вводит имя и email и подтверждает запись.
7. Видит страницу подтверждения: что, когда, с кем.

Владелец:

8. Открывает список предстоящих встреч и видит новую запись (тип, дата, время, гость) среди встреч всех типов.
9. Этот слот пропадает из свободных у всех типов встреч, в том числе у других типов с пересекающимся временем.

## Обязательные функции

- Владелец один и задан заранее.
- Владелец создаёт типы встреч: название, описание, длительность.
- Владелец видит список предстоящих встреч всех типов.
- Гость без регистрации выбирает тип встречи и видит календарь на 14 дней вперёд.
- Гость бронирует свободный слот, длительность слота равна длительности типа встречи.

## Ограничения

- Нет авторизации, личных кабинетов, интеграций с внешними календарями и уведомлений.
- Окно записи 14 календарных дней, сдвигается со временем.
- Одно время нельзя занять дважды, даже разными типами встреч, включая частичное пересечение. Встреча может начинаться в момент окончания предыдущей.
- Правило о пересечениях действует и для одновременных запросов.
- Приложение собирается в Docker-образ и запускается в контейнере.
- Данные можно хранить в памяти процесса. Тогда перезапуск сбрасывает записи, и это нужно указать в README.

## Требования к API

- Контракт описывается на TypeSpec.
- Из контракта генерируется OpenAPI-спецификация.
- Клиентский SDK для фронтенда генерируется из OpenAPI. Генератор должен существовать для языка фронтенда.
- Серверные типы и маршруты генерируются, если фреймворк это поддерживает. Иначе бекенд реализуется по контракту и проверяется тестами.
